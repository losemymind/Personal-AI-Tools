# 决策：触发评测的词重叠启发式维持现状，明确标注为「词面覆盖代理指标」

## 基本信息
- 日期：2026-09-11
- 版本：skill-creator 0.9.22 → 0.10.0（本轮批次）
- 触发来源：评估 `utils.classify` 的词面重叠启发式是否存在更优低风险做法。

## 评估与决策（无代码行为变更，仅文档定性）
- 现状：`utils.classify` 用「拉丁词（≥2）+ CJK 二元组」的集合求交（≥2 个共享 token）作触发判定，**仅在 `run_eval --mode heuristic`（离线、无客户端 CLI）使用**；`--mode cli` 已用客户端**真实派发信号**（opencode 读 `tool_use` 事件 `tool=="skill"` + `input.name==技能名`）为权威信号。
- 备选方案与判断：
  - 同义词归一 / 语义相似度：需引入词典或模型，**有假阳假阴与过拟合风险**，非低风险 → 不采纳。
  - 「dual-signal 优先级」：已天然成立（mode 选择即优先级；cli 覆盖 heuristic）。
  - token 边界：启发式已是词级 + CJK 二元组，进一步收紧会伤 CJK 召回。
- **结论**：无明确更优且低风险的方法 → **维持现状**；在 `utils.classify` docstring、`run_eval.py` 模块 docstring / `--mode` help、`SKILL.md` 阶段 7 明确标注其为**词面覆盖代理指标**（只度量共享措辞、不代表真实触发），其固有假阴/假阳**不作为缺陷上报**。

## 验证结果
- 无逻辑改动；仅文档/文案。全量 pytest 不受影响（本轮 skill-creator 167 → 184 由其他项贡献）。
- `validate_skills.py --strict --dir skills/skill-creator` 与能力库 strict 全绿。

## 学习点
- **代理指标要标注为代理**：当离线启发式长期被当成「缺陷来源」反复提出时，正确的收口是把它明确定义为「仅代表词面覆盖」的代理指标，并保留真实信号（cli 派发）为权威，而不是为一个本质上不可消除的重叠现象持续改描述。
- **不做低收益的高风险改动**：同义词/语义归一看起来更「准」，但引入不确定性，反而破坏可复现的确定性评测。
