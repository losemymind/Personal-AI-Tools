## 记录与再次压缩

1. 同一主题优先更新现有章节，注明事件日期、有效决定和替代关系；独立新事件可先记 `YYYY-MM-DD-<slug>.md`，成熟后合并并更新映射。
2. 最小记录：**问题/证据 → 来源/许可 → 决定与理由 → 验证方式和结果 → 未解决事项**。技能对比还需候选与同场景产出证据；仅有结构分时明确“待任务验证”。
3. 保留未知、未测、未采纳与被撤销的误报，不把阶段性“测试全绿”压成“没有缺陷”。统计数字注明当时范围，不机械累加；脚本名使用当前名称，上游原名和历史文件名仅作来源标识。
4. 合并后同步文档、账本、审计与测试引用，再删除旧正文；成品不留第二套原文或跳转壳。来源、日期、目标锚点由映射保留，已提交原文可从 Git 历史恢复；未提交原文不能假设已被 Git 保存。
