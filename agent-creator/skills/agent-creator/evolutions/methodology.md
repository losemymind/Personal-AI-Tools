# 方法论、评审与发布

<a id="writing"></a>
## 09-09：描述与引用纪律

**问题与决定**：references 曾互相导读、出现不存在的安装脚本名；description 混入流程摘要会削弱触发。采纳以下规则并同步入口、模板、质量条和验证器：

- references 从 SKILL.md 一层深按需导读，不互链成图；超过 100 行给目录，超大文件附检索提示。删除幽灵安装器引用，写明实际可用工具。
- description 写“职责 + 调用时机”，目标单行、≤200 字符、无尖括号占位符，不写步骤摘要；验证器上限为 300 字符，跨行/占位符目前是 advisory。
- 触发失败先分假阴性、假阳性与 run_error，执行故障不能靠改 description 掩盖。
- 当时 9 项回归及 32 代理 strict 通过。初期质量条曾由 5 增到 6，09-10 加入安全护栏后统一为 **7 项**；旧计数不再作为规范。

早期自包含扫描会漏掉没有路径分隔符的孤立脚本名；自动检查不能替代对加载层级和工具是否真实存在的审核。

<a id="review"></a>
## 09-10—09-11：AI 评审闭环

用户要求由作者代理修订、独立评审代理反馈。采纳 `agents/agent_reviewer.md`，反馈为 `review.json`：`verdict: pass|revise` 与可执行 `issues[]`；作者依据反馈继续修订，pass 或达到 `max-iterations`（默认 5）停止，达到上限不等于通过。

客观前置门为 `agent_validate.py --strict`；主观质量、职责边界与权限可执行性由评审子代理判断。普通评审无需人工介入，**授权与高风险升级仍保留人工门**。09-11 修正 reviewer 标尺为 7 项。契约与入口路由有回归覆盖，但这些检查不证明每次评审判断正确。
