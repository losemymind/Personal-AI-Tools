## 记录与再次压缩

1. 同主题优先更新现有章节，注明事件日期与替代关系；独立新事件可先记 `YYYY-MM-DD-<slug>.md`，成熟后合并并更新映射。
2. 最小记录：**问题/证据 → 来源/许可 → 决定与理由 → 验证结果及范围 → 未解决事项**。导入需保留本地候选是否存在；对比需区分结构筛查与同场景任务证据。
3. 保留未知、未测、未采纳、误报修正及已接受限制；不补造许可、测试结果或独立原创声明。
4. 合并后同步文档、台账、审计与测试引用，再删除旧正文；不留第二套副本或跳转壳。Git 可恢复的版本及未提交事件在映射中注明。
