# 代理解剖（Agent Anatomy）

解释 AGENT.md 文件的每个组成部分与底层工作原理，与 skill-anatomy 平行。

## 基本文件夹结构

```
agents/
└── my-agent-name/
    ├── AGENT.md              ← 必需：代理定义（frontmatter + 身份/边界/协作）
    ├── references/           ← 可选：按需加载的深化文档（领域准则、协作协议）
    └── README.md             ← 可选：附加说明
```

**关键规则：** 只有 `AGENT.md` 是必需的。安装到客户端时，兼容单文件（直接复制 .md）或目录（复制整个文件夹）两种形式（由 `install_agent.py` 处理）。

## AGENT.md 结构

1. **前置元数据（frontmatter）** — `---` 包裹的 YAML
2. **内容（主体）** — 身份/职责/权限/协作

## 前置元数据要点

- `name`：kebab-case，与目录名一致（客户端常以文件名/目录名作为代理标识）
- `description`：触发依据（何时被调用），前端加载特定术语
- `mode`（opencode）：`primary`（用户直接对话）/ `subagent`（被主代理调用）/ `all`
- `tools` / `permission`：最小权限的关键声明位置
- 字段完整对照与兼容矩阵见 `references/agent-template.md`

## 内容推荐结构

1. **角色定位** — 1-2 句，它是谁
2. **职责范围** — 必须做 / 拒绝做（边界，代理质量的核心）
3. **工作方式** — 判断标准与流程要点
4. **工具与权限** — 允许列表 + 禁止列表，最小权限
5. **协作协议** — 何时被调用、汇报格式、升级路径
6. **完成标准** — 产出验收（可验证）
7. **限制与边界** — 做不到的事

## 渐进式披露（三层加载）

1. **frontmatter 元数据** — 始终在上下文，决定是否被调用
2. **AGENT.md 主体** — 被调用时加载（理想 <500 行）
3. **捆绑资源（references/）** — 按需加载

## 代理 vs 技能

| 维度 | 技能 | 代理 |
|---|---|---|
| 回答的问题 | 怎么做 | 谁来做 |
| 触发方式 | 用户提到场景 | 被调用/被分派 |
| 核心内容 | 步骤与规则 | 身份、边界、权限、协作 |
| 生命周期 | 一次触发执行 | 常驻参与、可调度 |
| 例子 | code-review 流程 | reviewer 代理 |

## 使用场景判断

- 单个可描述流程 → 技能
- 持续角色、权限、协作 → 代理
- 代理内部可引用技能，技能不引用代理

## 常见错误

- ❌ 把代理写成步骤清单（那是技能）
- ❌ 职责边界含糊（没有「拒绝做」）
- ❌ 工具权限过大（给与职责无关的权限）
- ❌ 没有升级路径（代理卡死时无人接管）
- ❌ 完成标准不可验证（"尽力而为"式验收）
