# 代理质量门槛（Agent Quality Bar）

代理必须达到以下 **7 项质量检查** 才能视为合格，其中部分由 `scripts/validate_agents.py` 自动执行（标注「自动」）。

## 7 项质量检查

### 1. 元数据完整（自动）

- `name`：kebab-case，与目录/文件名一致
- `description`：≤200 字符（验证器上限 300），单行、含「做什么 + 何时被调用」、无 `<`/`>` 占位符（description 是唯一无条件加载的触发面）
- 不写 `version`/`tools_clients`/来源字段：来源/作者/日期记入库根创建记录账本 `AGENTS-RECORDS.md`，版本以 git 提交历史为准

### 2. 职责边界清晰（自动章节检查）

主体必须有「职责范围」章节，且**同时包含「必须做」与「拒绝做」**——边界是代理质量的核心。

### 3. 最小权限（自动检测 + 评审子代理复核）

- `tools`/`permission` 显式声明
- 破坏性工具（execute/bash 写操作/删除）不默认授予
- 高危动作显式声明或拒绝
- （评审子代理）工具是否与职责匹配，无无关权限

### 4. 协作协议完整（自动章节检查）

主体必须有「协作协议」章节，含：
- 何时被调用
- 汇报格式
- **升级路径**（何时停下交还人类）

### 5. 完成标准可验证（自动章节检查）

主体必须有「完成标准」章节，产出验收是**可验证的检查项**，而非「尽力而为」。

### 6. 渐进披露与引用纪律（自动查悬空 + 评审子代理查层级）

- 主体克制（理想 <500 行），细节下沉 `references/`
- references 由 SKILL.md 一层深导读，references 之间不互链成图（评审子代理检查层级）
- 主体/资源本地引用不悬空（自动；验证器「本地引用」项）

### 7. 安全护栏（自动扫描 + 评审子代理复核）

- AGENT.md 与捆绑资源无明文密钥/凭据、无危险远程执行管道（自动；`<!-- security-allowlist -->` 可按行/块豁免）
- 攻击性代理必有「AUTHORIZED USE ONLY / 仅限授权使用」声明 + 执行前用户确认
- 需要凭据/权限/生产数据的场景升级给用户（详见下方「安全护栏（代理专属）」）

> 上述 7 项与 `references/agent-comparison.md` 的「质量 7 维」一一对应。

## 验证器使用

```bash
# 标准模式（警告不阻断）(默认扫 agents/ 或指定目录)
python scripts/validate_agents.py [--dir <agents目录>]

# 严格模式（警告即失败，适合 CI）
python scripts/validate_agents.py --strict
```

## 验证器检查项一览

- [x] frontmatter 有效 YAML 且为映射
- [x] `name` 存在、kebab-case、与目录/文件一致
- [x] `description` 存在、为字符串、未超长
- [x] 主体非空
- [x] 「职责范围」章节存在（含必须做/拒绝做）
- [x] 工具/权限声明存在
- [x] 「协作协议」含升级路径
- [x] 「完成标准」存在
- [x] 本地引用不悬空（fenced 代码块豁免）
- [x] 明文密钥/凭据扫描（AGENT.md 与捆绑资源；`<!-- security-allowlist -->` 可按行/块豁免）
- [x] 危险远程执行管道扫描（围栏/缩进代码；可豁免）
- [x] 显式 `--dir` 下无代理定义时失败（防止错路径静默全绿）
- [x] 跳过隐藏目录与符号链接

## 支持级别

| 级别 | 含义 |
| :-- | :-- |
| **未验证** | 新建代理草稿 |
| **已验证（--strict 通过）** | 结构、元数据、边界、协作全部达标 |
| **试运行验证** | 在真实场景被调用过一次并符合预期（评审子代理确认） |

## 安全护栏（代理专属）

- 最小权限：只授予职责必需的工具
- 破坏性动作默认拒绝，涉及时显式声明
- 攻击性代理（渗透/红队）：必须含「AUTHORIZED USE ONLY / 仅限授权使用」声明 + 执行前用户确认
- 身份与权限必须一致：不创建「伪装正常身份但授权越界」的代理
- 需要凭据/权限/生产数据的场景：升级给用户，不「尽力而为」
