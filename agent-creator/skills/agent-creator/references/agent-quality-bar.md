# 代理质量门槛（Agent Quality Bar）

代理必须达到以下 **5 项质量检查** 才能视为合格，其中部分由 `scripts/validate_agents.py` 自动执行（标注「自动」）。

## 5 项质量检查

### 1. 元数据完整（自动）

- `name`：kebab-case，与目录/文件名一致
- `description`：≤200 字符（验证器上限 300），包含「做什么 + 何时被调用」
- 推荐声明：`version`（semver，生命周期记账）、`tools_clients`

### 2. 职责边界清晰（自动章节检查）

主体必须有「职责范围」章节，且**同时包含「必须做」与「拒绝做」**——边界是代理质量的核心。

### 3. 最小权限（自动检测 + 人工复核）

- `tools`/`permission` 显式声明
- 破坏性工具（execute/bash 写操作/删除）不默认授予
- 高危动作显式声明或拒绝
- （人工）工具是否与职责匹配，无无关权限

### 4. 协作协议完整（自动章节检查）

主体必须有「协作协议」章节，含：
- 何时被调用
- 汇报格式
- **升级路径**（何时停下交还人类）

### 5. 完成标准可验证（自动章节检查）

主体必须有「完成标准」章节，产出验收是**可验证的检查项**，而非「尽力而为」。

## 验证器使用

```bash
# 标准模式（警告不阻断）(默认扫 agents/ 或指定目录)
python scripts/validate_agents.py [--dir <agents目录>]

# 严格模式（警告即失败，适合 CI）
python scripts/validate_agents.py --strict
```

## 验证器检查项一览

- [x] frontmatter 有效 YAML 且为映射
- [x] `name` 存在、kebab-case、与目录/文件一致
- [x] `description` 存在、为字符串、未超长
- [x] `version` 若存在则要求 semver `x.y.z`
- [x] 主体非空
- [x] 「职责范围」章节存在（含必须做/拒绝做）
- [x] 工具/权限声明存在
- [x] 「协作协议」含升级路径
- [x] 「完成标准」存在
- [x] 本地引用不悬空
- [x] 跳过隐藏目录与符号链接

## 支持级别

| 级别 | 含义 |
| :-- | :-- |
| **未验证** | 新建代理草稿 |
| **已验证（--strict 通过）** | 结构、元数据、边界、协作全部达标 |
| **试运行验证** | 在真实场景被调用过一次并符合预期（人工确认） |

## 安全护栏（代理专属）

- 最小权限：只授予职责必需的工具
- 破坏性动作默认拒绝，涉及时显式声明
- 攻击性代理（渗透/红队）：必须含「AUTHORIZED USE ONLY / 仅限授权使用」声明 + 执行前用户确认
- 身份与权限必须一致：不创建「伪装正常身份但授权越界」的代理
- 需要凭据/权限/生产数据的场景：升级给用户，不「尽力而为」
